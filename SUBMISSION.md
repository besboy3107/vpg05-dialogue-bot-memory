# VPg05 - отчёт о выполнении задания

## Реализованные требования

1. Создан проект с виртуальным окружением, `requirements.txt` и `.env` с 5 ключами (Pinecone, OpenAI API key, OpenAI Base URL, Pinecone index name, Telegram token).
2. Написан модуль `pinecone_manager.py` — класс `PineconeManager` с полным набором методов: upsert/query/fetch/delete/stats/update_metadata.
3. Добавлена поддержка `OPENAI_BASE_URL` — параметр принимается и в конструкторе, и из `.env`, передаётся в клиент OpenAI.
4. Реализована умная фильтрация дубликатов через косинусное сходство: глобальная переменная `SIMILARITY_THRESHOLD = 0.85` управляет порогом. Перед записью метод `upsert_vector` проверяет ближайший вектор в базе — если `score >= 0.85`, обновляет существующий слот (`action: updated`), иначе добавляет новый (`action: inserted`).
5. Метод `upsert_vector` возвращает словарь с полями `action`, `similarity_score`, `existing_id`.
6. Добавлен ручной тестовый скрипт в `if __name__ == "__main__"` — проверяет подключение к Pinecone и логику дедупликации на тестовых фразах.
7. Создан `bot.py` — Telegram-бот на `pyTelegramBotAPI` с краткосрочной памятью (история диалога в оперативной памяти) и долговременной (векторная база Pinecone).
8. Исправлена обработка метаданных: `first_name` и `last_name` берутся только если присутствуют, иначе используется `пользователь_{id}` — бот не падает при неполном профиле.
9. В Pinecone сохраняется **только текст пользователя** — ответы бота и служебные поля (`bot_response` и т.п.) не записываются.
10. Каждое обращение к памяти логируется: `action=inserted | score=— | 'текст'`.

## Доказательство проверки

Ручной тест модуля:

```powershell
$env:PYTHONUTF8=1; .\.venv\Scripts\python pinecone_manager.py
```

Результат:

```
--- Тест записи с проверкой дубликатов ---
  [NEW] action=inserted score=n/a   | Привет
  [NEW] action=inserted score=n/a   | Зачем люди хотят лететь на Марс?
  [NEW] action=inserted score=n/a   | Я бы хотел полететь на Марс
  [DUP] action=updated  score=0.892 | Я бы не хотел полететь на Марс
  [NEW] action=inserted score=n/a   | Я очень люблю пиццу
```

Критерий задания выполнен: похожая фраза `Я бы не хотел полететь на Марс` распознана как дубликат (`score=0.892 >= 0.85`) и не создала новую запись — обновила существующую.

Проверка импортов бота:

```powershell
$env:PYTHONUTF8=1; .\.venv\Scripts\python -c "import bot; print('bot.py imports OK')"
```

Результат: `bot.py imports OK`

## Как запустить

1. Заполнить `.env` (шаблон в репозитории — ключи убраны).
2. Создать виртуальное окружение и установить зависимости:
```powershell
python -m venv .venv
.\.venv\Scripts\pip install -r requirements.txt
```
3. Запустить бота:
```powershell
.\.venv\Scripts\python bot.py
```
4. Написать боту в Telegram любое сообщение. В логах терминала будет виден результат записи в память.

## Валидация умной памяти

Отправить боту подряд:
- `Хочу полететь на Марс` → лог: `action=inserted`
- `Я бы хотел полететь на Марс` → лог: `action=updated` (дубликат по смыслу)
- `Я люблю пиццу` → лог: `action=inserted` (новая тема)

## Архитектурное решение

Проект разделён на два файла с чёткими обязанностями. `pinecone_manager.py` — независимый модуль для работы с Pinecone: его можно тестировать отдельно без Telegram. `bot.py` — только интерфейсный слой, который использует менеджер как инструмент. Краткосрочная память хранится в dict по `user_id` и обрезается до последних 10 пар, долговременная — в Pinecone с автоматической дедупликацией. Такое разделение позволяет заменить Telegram на любой другой интерфейс, не трогая логику памяти.
